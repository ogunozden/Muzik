## Threat Model

The reviewed subsystem batch-generates search-only candidate review rows for missing external references in the 3000-entry SymbTr catalog, serves the generated queue through bounded local API pagination and filtered export, displays the queue in the curation dashboard, and validates generated queue artifacts before closure. Assets include catalog metadata, research source profiles, generated queue artifacts, accepted candidate manifests, candidate review rows, and operations UI state. Trust boundaries are local JSON profile/config files, generated output under `output/external-reference-coverage`, route query parameters used only for local filtering, POST body filters used only for local export, and dashboard display of artifact paths/counts/search links. Security invariants: research profiles must have stable ids, bounded trust weights, and `{query}` templates; generated search candidates are not source evidence; `needs-review` and `conflict` rows never count as accepted curated references; review rows must not carry accepted source ids or source URLs; export reads only fixed project artifacts; output paths stay inside the project; API pagination/export size is bounded; no media is downloaded; and no operator token or secret is written to artifacts.

## Findings

### No findings

The diff did not introduce a plausible security vulnerability. Research profile rows are read from a fixed project path and validated for id shape, label presence, `{query}` template presence, and `trustWeight` range. Candidate review URLs are generated by replacing only the `{query}` placeholder with `encodeURIComponent(query)`, avoiding raw metadata injection into search URL parameters. The output filenames are constants under the existing `output/external-reference-coverage` directory, and writes pass through the existing project containment helper. Generated rows contain catalog metadata, profile ids, search URLs, and review status only; no remote content is fetched, downloaded, embedded, or marked accepted. The route reads the fixed queue artifact, caps candidate page size at 500, normalizes offsets to non-negative integers, caps filtered export at 20,000 rows, and applies status/profile/provider/text filters in memory without shelling out or reading caller-provided paths. The validator now rejects review rows that drift into accepted data (`accepted` status, source id, source URL), rejects profile/provider/trust drift, bounds review confidence to 0-100, and cross-checks queue counts against `summary.json`. The dashboard displays bounded rows, count/path metadata, ordinary outbound search links, and a separate read-only review queue export text area; accepted/auto-attach behavior remains tied to validated `accepted` bulk candidates.
